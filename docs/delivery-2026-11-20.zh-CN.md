# ztype：正式依赖与原生文字送达验收

日期：2026-11-20（UTC）

**ztype 已接入正式发布的 zuse-computer 0.2.1，并通过 11 项真实 GTK 输入验收。** 中文、日文、阿拉伯文、印地文、emoji、原生引擎插件和候选面板均按预期写入接收窗口；按住 Enter 时提交 ASCII 也正常。验收中的混合 UTF-8 文本对只读目标整串拒绝，错误输入和取消的组合不会提交旧候选。功能源码与原始结果固定在 [037de9972e169942ca6258d6aee6ba53711204f6](https://github.com/LIghtJUNction/ztype/commit/037de9972e169942ca6258d6aee6ba53711204f6)。

当前交付是可用的组合输入应用：紧凑候选窗、命令行、语言引擎、共享插件接口和显式目标送达已经连通。系统级 XIM、Wayland input-method、Windows TSF、macOS InputMethodKit 前端仍待实现。软件覆盖以实际验收的接收端和路径为准，完整替代 WowType 是后续产品目标。

## 2. 修复的具体问题

旧 X11 路径存在真实的错字问题：调用返回成功后，接收窗口中的文字仍可能错误。固定对照向真实 GTK 输入框发送 `Z 你好こんにちは مرحبا नमस्ते 🙂`，分别使用 zuse 0.1.1、0.2.0，以及正常接收和暂停接收 120 ms 两种状态。四次都返回退出码 0 和 `submitted`，四次存储文本都与目标不同。[完整对照与 Unicode 码点](https://github.com/LIghtJUNction/ztype/blob/b349b1c896d7bf3b736cd5d0d0ef8374274da98a/docs/evidence/unicode-baseline.json)

| 版本 | 接收端暂停 | 实际存储文本 |
| --- | --- | --- |
| 0.1.1 | 0 ms | `Z 你好こんにちは مرااا नसस्ेे 🙂` |
| 0.1.1 | 120 ms | `Z 好好こんにちは مبببا नम ` |
| 0.2.0 | 0 ms | `Z 你好こんにحح باااا ्््🙂🙂🙂 🙂` |
| 0.2.0 | 120 ms | `Z 你好こちははم حححبا न ` |

根因在于按键编号与文字内容之间隔着可变的键盘映射。旧路径临时修改某个按键编号对应的字符、发送事件，再复用或恢复映射；接收程序稍后处理事件时，看到的映射可能已经变化。正式修复移除了这条临时映射路径，改为在发送前完整检查字符串和键盘状态。[共享修复说明与实现](https://github.com/LIghtJUNction/zuse/blob/8cb97129feeed2eea82b52aefaaf0743a29122b1/docs/x11-utf8-delivery.md)

新的路径把布局外字符，以及按键仍被按住等不适合模拟键入的可打印文本，交给 AT-SPI 插入完整 UTF-8。AT-SPI 是桌面辅助功能接口，可以直接操作已确认的可编辑控件。共享层先核对 X11 焦点、目标身份和唯一的可编辑对象，再以字符位置处理选区、以 UTF-8 字节长度调用插入，并检查结果与光标。普通布局内按键保留原有事件路径；所有路径都在第一项输入动作之前选择完毕。[实现与 17 项原生记录](https://github.com/LIghtJUNction/zuse/blob/8cb97129feeed2eea82b52aefaaf0743a29122b1/docs/evidence/x11-utf8-review-2026-11-20.json)

消费者还补出了一个实际边界：面板收到 Enter 按下事件时，Return 键可能仍然处于按下状态。此前修复的第一版在这个状态下拒绝 ASCII 提交；最终公共修复让整串 ASCII 也进入上述确认插入路径，同时保留用户按键状态。这个反例和修复后的 11 项结果保存在[共享消费者回归证据](https://github.com/LIghtJUNction/zuse/blob/8cb97129feeed2eea82b52aefaaf0743a29122b1/docs/evidence/ztype-held-enter-2026-11-20.json)。

## 4. 错误边界与平台范围

错误结果说明操作进行到了哪一步。插入前发现目标不明确、不可编辑、只读、密码控件、服务不可用等条件时，确认插入路径返回 `Unsupported`，没有发送输入。插入开始后发生焦点变化、文本过滤、回调改写或超时，会返回 uncertain 语义，明确文字可能已经改变；ztype 不自动重试。这避免把真实发生的输入重复一次，也避免用回滚覆盖应用的新内容。[共享错误语义与回归](https://github.com/LIghtJUNction/zuse/blob/8cb97129feeed2eea82b52aefaaf0743a29122b1/docs/x11-utf8-delivery.md)

插入及选区处理由多个辅助功能调用组成，应用仍可能在调用间并发编辑。共享层采用有界检查，选区快照最多 65,536 个 Unicode 字符、262,144 个 UTF-8 字节，超过限制明确拒绝；检查与删除之间仍存在并发窗口。密码控件在读取内容之前被拒绝。普通按键事件的最终处理仍由接收程序决定，因此应用的对外输出继续使用提交语义。[固定实现](https://github.com/LIghtJUNction/zuse/blob/8cb97129feeed2eea82b52aefaaf0743a29122b1/src/accessibility/native/x11_input.rs)

| 使用范围 | 已有能力和证据 | 尚待完成 |
| --- | --- | --- |
| Linux X11、显式目标 | 本轮正式依赖构建及 11 项 GTK 实际输入通过 | 更多应用家族逐项验收 |
| XWayland | 可明确选择共享 X11 路径 | 独立 XWayland 接收端验收 |
| Windows、macOS | [首轮三系统 CI](https://github.com/LIghtJUNction/ztype/actions/runs/44634327653) 已通过原生构建、契约、插件和 CLI 检查 | 本轮更新后的外部软件输入实测 |
| 系统输入法服务 | 组合状态和插件接口已可复用 | XIM、Wayland input-method、TSF、InputMethodKit 前端 |
| 语言能力 | 起步拼音表、罗马字转假名、Unicode、原文、自定义表和插件 | 大词库、整句预测、汉字转换、用户适应等独立引擎工作 |

这条 Linux 输入路径没有 Fcitx5 依赖。文字的 UTF-8 存储、语言转换与字形排版分别由不同层负责；本轮验收覆盖存储文字，复杂文字的最终显示还受接收软件字体和塑形能力影响。直接及运行期 Rust 依赖来自 Project Z；类型插件宏在编译时使用 proc-macro2、quote、syn、unicode-ident，完整构建的依赖图保留了这一区分。[锁定的实际依赖](https://github.com/LIghtJUNction/ztype/blob/037de9972e169942ca6258d6aee6ba53711204f6/docs/evidence/zuse-0.2.1-registry.json)

## 5. 资源与复现

本轮最终验收在独立 systemd cgroup 中执行，运行前读取内核设置确认限制生效。只使用一个 Cargo 编译任务，低优先级运行，并保留至少 3 GiB 主机可用内存；监督器在触及保留线时只停止自己的单元。[完整资源记录](https://github.com/LIghtJUNction/ztype/blob/037de9972e169942ca6258d6aee6ba53711204f6/docs/evidence/zuse-0.2.1-resources.json)

| 项目 | 实际记录 |
| --- | --- |
| 内存 hard / high | 768 MiB / 576 MiB |
| Swap / CPU | 0 / 单核 75% |
| 优先级 / Cargo 任务 / Rust 测试线程 | nice 19 / 1 / 1 |
| cgroup 峰值内存 | 606,208,000 字节，约 578.125 MiB |
| 主机最低 MemAvailable | 5,000,527,872 字节，约 4.66 GiB |
| 退出与 OOM | 退出码 0；OOM 与 OOM kill 均为 0 |

原生夹具使用显式高位显示号、原子互斥、私有认证和独立 D-Bus / AT-SPI 服务，并检查实际就绪显示号与请求一致。它只清理自身进程，不修改日常桌面和输入法设置。Rust 1.100、Linux 图形开发库、GTK、Xvfb、xauth、xdpyinfo、xdotool、D-Bus 工具及 at-spi2-core 是复现环境要求。[已验收脚本](https://github.com/LIghtJUNction/ztype/blob/037de9972e169942ca6258d6aee6ba53711204f6/scripts/test_native.py)和[手动工作流环境](https://github.com/LIghtJUNction/ztype/blob/037de9972e169942ca6258d6aee6ba53711204f6/.github/workflows/ci.yml)给出完整参数。

```sh
git clone --recurse-submodules https://github.com/LIghtJUNction/ztype.git
cd ztype
git checkout 037de9972e169942ca6258d6aee6ba53711204f6
git submodule update --init --recursive
cargo clippy --all-targets --locked -- -D warnings
cargo build --bin ztype --example kana_plugin --locked
python3 scripts/test_native.py --binary target/debug/ztype --plugin target/debug/examples/libkana_plugin.so
```

这组命令复现构建与原生行为；上表的资源限制属于本次验收执行记录，直接运行命令不会自动设置相同 cgroup。常规迭代采用本机验收，原生工作流保留手动触发，本轮未重复触发 CI。
